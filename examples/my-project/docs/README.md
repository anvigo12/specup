# Team documentation

Not governed, and that is deliberate. A governed document is one an id points at and a check
can reach; a runbook, an onboarding note or a diagram somebody sketched is not improved by
giving it an id, and giving it one only adds a reference that has to keep resolving.

The rule is worth stating because the opposite instinct is common: once a project has
governance, everything looks like it should be inside it. Process must earn its place — an
artifact that does not enable a decision, an execution, a verification or an audit is
overhead, whatever it is called.
